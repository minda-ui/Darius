**Why it is split this way** (owner's instruction, 2026-09-23, *"split by period"*). Drive has no patch
API, so a whole file is re-emitted for one new row. Splitting by table would not help — all three tables
are append-only and every session touches at least one. Splitting by period does, because a settled row
is never touched again.

**There is no size threshold any more** — owner's instruction, 2026-09-28, charter **v33**: *"we don't have
anymore size restrictions."* **This file is not snapshotted on byte count again.** The three snapshots above
stand and stay findable by name; a further split would need a reason of its own, the owner asking or the
file becoming hard to navigate.

*What this supersedes, kept rather than deleted: the previous version of this paragraph argued that v32's
cheaper write **did not** relax the threshold, because ~25 KB was about readability and findability rather
than the cost of a write. **The owner overruled that the same day.** Recorded because the reasoning was
published here under my name and a silent deletion would read as if it had never been held.*

*The cost of renaming rather than rewriting is that each snapshot keeps the header it had when it was
live, so it still describes itself as the file `CLAUDE.md` §0 sends you to. It does not. The filename and
this table are authoritative.*
